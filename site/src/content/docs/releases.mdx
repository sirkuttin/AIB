## 0.15.0-beta

[Downloads on GitHub](https://github.com/sirkuttin/AIB/releases/tag/v0.15.0-beta)

> **Beta.** Builds are not code-signed. Expect rough edges. Install and download notes are the same as in [0.1.0 beta 1](https://github.com/sirkuttin/AIB/releases/tag/v0.1.0-beta.1).

AIB 0.15.0 beta gives every agent a smaller, clearer set of AIB tools and makes the right panel tell the truth about what is running. AIB's 30 tools are now 6. Codex, Gemini and Qwen Code reach them, chats that are out of date restart themselves to pick them up, and unfinished helper work goes to your main agent to land or discard. Everything runs on your PC, with no AIB cloud and no account.

### What's new

#### Six AIB tools: every agent gets the same short list

- **Cross-agent:** the same six tools (`publish`, `artifacts`, `doc`, `drawing`, `helper`, `merge_into_project`) go to every agent that can use AIB's tools. Each has a short description and takes an `action`, so an agent reads six entries, not thirty.
- **Old tool names still work,** for chats and prompts that use them.
- **Approvals work per action:** reading a doc runs automatically; restoring one asks. Your existing allow and ask rules map onto the new tools.
- **Local:** the tools run inside AIB on your PC. Artifacts, docs and drawings stay in your project.

#### Codex, Gemini, Qwen Code and Maki: AIB's tools reach more agents

- **Codex sees AIB's tools directly** and waits for them to start before its first turn, so the first message already has them. Your own MCP servers for Codex stay as they are.
- **Gemini CLI gets AIB's tools.** AIB marks the project folder (and the helper's worktree copy) as trusted in AIB's own trust file.
- **Qwen Code's MCP tools now reach the model,** so AIB's tools work there.
- **Maki's own tools run without asking for approval.**
- **The Copilot card says plainly** that AIB's tools are not available there.

#### Chats that pick up new tools: out-of-date chats restart themselves

- **A chat restarts when it is idle,** never mid-turn and never with background processes running, to pick up the tools or prompt of the current AIB. The chat shows one line: "Restarted to pick up new AIB tools".
- **A chat that fails to restart stays open** with the error shown, and AIB tries once per version.
- **Lead chats keep their helper tools after an update.**

#### Left-over helper work: your main agent lands it or discards it

- **The `helper` tool has `work_list`, `work_land`, `work_diff` and `work_discard`.** Work from a finished subagent or helper that did not land goes to the main agent, which reads the diff and lands or discards it.
- **The Changes tab shows at most "Being handled by &lt;chat>".** The "Left over" list is gone, so there is no list for you to work through.
- **The landed check is reliable.** It follows files through renames and the move to `app/`, so work that is already in main is not reported as left over.
- **Landing waits for a builder's own processes,** and a finished builder lands while others are still working.
- **Landing messages appear in the chat only when the main agent has to act.**

#### Activity: only what is running, with the rest folded away

- **Working covers subagents, helpers and their background runs,** everywhere it shows, including the dot on the project dropdown.
- **Activity lists only running processes.** Finished helpers and subagents fold into "N finished" with grey dots. Failed subagents that changed nothing fold there too.
- **Click a helper to open its history.** If it cannot open, the error shows in the panel.
- **Background tool rows show the command,** not an id.

#### Kill by PID: AIB refuses kill-by-name in every chat

- **Cross-agent:** commands like `taskkill /im`, `pkill` and `killall` are refused in every chat, and the agent is told to find the process and kill it by PID.
- **Local:** this keeps an agent from ending your other programs, or another chat's processes, that share a name.

#### Big pasted pictures: shrunk, not refused

- **A large picture is reduced in the page** before it is attached, on the PC and the phone. The chip shows the new size.

#### One data folder named AIB: and a script you run, not a surprise

- **The folder is `%LOCALAPPDATA%\AIB`** on Windows, `~/Library/Application Support/AIB` on macOS and `~/.local/state/aib` on Linux, marked by a file named `aib-data.json`.
- **An existing `AgentStudio` folder moves with a one-time script** you run yourself: `deno run -A work/migrate/rename_data_folder.ts`. `--dry-run` shows the plan and `--undo` puts everything back. AIB never moves or copies your data on its own, and keeps using the old folder until you run it.
- **The script sets an old install aside,** copies your data, checks the file count and size, repairs worktree links and keeps the old folder.

#### Repo layout: `app/`, `docs/`, and no Python

- **The source is in `app/`** (it was `outputs/agent-studio`), and the project docs are in `docs/`.
- **The Python reference and the Python tests are retired.** The test fakes and end-to-end tests run on Deno and Node.

### Fixes
- **Send now waits for Claude's running command:** the row says "Sends when the running command finishes", the command runs to its end, and your message goes in right after. Nothing is cancelled.
- **Chats open fast:** Project changes and the agents list read saved results and one process snapshot, so a project with many old builder branches opens without waiting on git.
- **Phone access connects:** AIB's own window never takes the phone port.
- **Stuck "Working" is fixed:** a finished subagent's live background runs show in Activity and keep the chat Working, and end when they end.
- **AIB lands a builder only when it has finished its work.**
- **Dead processes show as ended** in Activity.
- **An idle chat expanded in Activity opens its finished fold.**
- **Finished helpers fold into "finished"** with a grey dot, never green.
- **Lead chats keep their helper tools after a keeper take-over.**

### Known issues
- **Helpers are still refused in WSL projects.** Subagents work there.
- **GitHub Copilot gets no AIB tools.** The Copilot card says so.
- **The data-folder move is a one-time script you run,** with AIB and its keeper closed. Until then AIB keeps using `AgentStudio`.
- **On macOS, finished-subagent clean-up cannot read the labels** on a subagent's processes, so it cannot tell which ones to shut down.
- **A chat that is mid-turn or has background processes keeps its old tools** until it is idle, then restarts.
- Carried over from 0.14.0 beta.

### Tested
- 3,118 Deno tests and 1,753 Node tests on Windows, including end-to-end runs of the real Claude Code for Send now and subagent landing.
- Update and keeper take-over from the previous build.
- Test builds 13–19 used daily on Windows, including phone access over Tailscale.

## 0.14.0-beta

[Downloads on GitHub](https://github.com/sirkuttin/AIB/releases/tag/v0.14.0-beta)

> **Beta.** Builds are not code-signed. Expect rough edges. Install and download notes are the same as in [0.1.0 beta 1](https://github.com/sirkuttin/AIB/releases/tag/v0.1.0-beta.1).

AIB 0.14.0 beta lets any agent do more of the work and lets your own PCs share it. A local model server can run behind Claude Code, Codex, Maki or Qwen Code. Helpers from other agents are on by default and clean up after themselves. Two of your PCs can sync a project's `aib-shared/` files and AIB docs over your own Tailscale. Everything runs on your PCs, with no AIB cloud and no account.

### What's new

#### Model servers: run a local model behind the agent you already use

- **Cross-agent:** one server works behind Claude Code, Codex, Maki and Qwen Code. Each agent you switch on under **Use with** gets its own entry in New chat, such as "Claude Code · strata", beside the normal one. The normal entry and its sign-in are untouched.
- **Local:** the server runs on your own machine or network, such as a llama-server. AIB talks to it directly; nothing goes through AIB.
- **Settings › Model servers** holds the name, the address, an optional key (never shown back) and the model, read from the server's `/v1/models`. AIB finds which API kinds the server speaks.
- **A server that does not answer is greyed out** in New chat, on the PC and the phone. AIB checks when New chat opens and keeps the answer for 30 seconds.
- **Check, Edit and Remove** are small icons on each server row.
- **Maki and Qwen Code take their address from the server switched on for them.** A one-time script, `work/migrate/beta_addresses_to_model_servers.ts`, moves addresses you saved earlier.
- **Helpers use these entries too:** a main chat can start a helper on a model-server entry. If the server is down, the main agent is told plainly.

#### Helpers from other agents: on by default, answered where you work

- **Cross-agent:** a main chat can start helpers on other agents, such as Codex or Gemini, or on a model-server entry. Each helper works in its own worktree and branch.
- **Helpers are on by default,** and the setting is out of Experimental.
- **Approvals show in every place you answer:** the helper's row in Activity (Allow and Deny), a labelled card in the main chat, the inbox, the desktop toast and the phone.
- **Routine edits and test runs inside the helper's own worktree are allowed automatically.** Anything else asks.
- **Helpers stay out of the left chat list.** They are named "&lt;title> (&lt;agent>)", after the job.
- **A finished helper shuts down with everything it started:** its agent and every process under it.
- **A helper that asks a question shows as waiting,** its report keeps its beginning and its end, and a closed helper can still be merged.

#### Subagent clean-up: a finished subagent stops what it started

- **Cross-agent:** Claude Code and Codex subagents, on Windows and in WSL.
- **Local:** AIB marks each shell command a subagent runs and, when the subagent finishes, ends the processes it left running.
- **Activity shows the result:** those rows read "stopped: subagent finished", and the main chat gets one line.

#### PC to PC sync: your docs and shared files on every PC you own

- **Local:** PCs pair over your own Tailscale. No cloud, no account.
- **Settings › Sync** pairs two PCs: start a sync chain on one, type its six words on the other, check the two words and approve.
- **A project syncs when both PCs have its switch on.** AIB matches projects by their git remote and suggests matches by name. Each project has two switches: AIB docs and `aib-shared/`.
- **Cross-agent:** `aib-shared/` files and AIB docs come across, whichever agent wrote them. Doc edits merge block by block, and text files merge line by line.
- **A conflict can be kept on both sides.** The conflict pill in Files has **Compare**, **Keep this** and **Keep other**.
- **Syncing is visible:** a sync mark in the sidebar, one Activity line per batch, and a waiting state when the other PC is off or a WSL distro is stopped.
- **WSL projects sync too.**

#### Send later: schedule a prompt

- **The Send menu has Send later…** with quick picks and a date. The message shows as a "Scheduled for …" card with edit, send now and remove.
- **The host sends it at the time,** with the chat closed or AIB's window closed. A time missed while AIB was off fires when AIB starts.
- **The phone shows scheduled messages and can cancel them.**

#### Interrupt and send: waits for the turn to stop

- **Send now never cancels running work.** For agents that cannot take a message mid-turn, your message stays first in line and goes the moment the turn ends.

#### WSL subagents: their own copy, inside the distro

- **Claude Code and Codex subagents in WSL projects work in their own worktree inside the distro** and land the way they do on Windows. Hooks reach AIB through the helper's tunnel, with no network port.
- **Their shell commands are tagged,** so a finished WSL subagent's processes shut down inside the distro.

#### Right panel: Activity, Changes, Artifacts and Docs for the whole project

- **Activity** lists the project's working chats with their subagents and processes. Idle chats sit below, collapsed, and every conversation of the project is listed.
- **Changes, Artifacts and Docs are project tabs.** Every artifact of the project and every doc opens there, and a doc pops out from its header.
- **The panel keeps its width when you switch chats.** Tabs keep their names at the 320 px default and shrink to icons below about 315 px.
- **Activity heads read like "2 subagents · 1 process".** Process dots are small squares; subagent dots stay round.

#### Gemini and Antigravity: approvals read correctly

- **Allow rules understand the permission requests of Gemini CLI 0.70.0 and Antigravity CLI 1.5.11,** recorded from the real programs. Helper rules and your own rules apply to them as to Codex.

#### OMP is removed

- **OMP is out of New chat (PC and phone) and Settings.** Saved OMP chats stay in the list as read-only history, with one line in place of the message box. A default agent set to OMP falls back to Claude Code. AIB never touches your OMP install or `~/.omp`. OpenAI-compatible servers run behind Codex, Maki and Qwen Code under Model servers.

### Fixes
- **Codex helpers start with codex-acp 2.6.** AIB reads the edit-in-workspace mode from the modes the agent offers, after the adapter renamed `auto` to `workspace-write`, and never picks a broader one.
- **Closing a chat whose keeper connection died takes under a second.** AIB skips the graceful waits for a connection that is gone.
- **Landing is more reliable.** A busy parent chat shows "Waiting to land" and is woken, a failed landing wakes the chat that started the builder, and work already landed by hand is not reported as a conflict.
- **The message box keeps the caret** after a queued message's card goes away and after the first message of a new chat.
- **Linux .deb update installs.** AIB saves the download with permissions the root installer accepts (644, 755, 755), and the package leaves out the stray `usr/lib/aib/dev.aib.app.desktop`.
- **Agents give `sudo` commands to your terminal** in a bash block for **Run in terminal**, and carry on when you say it is done. AIB never sees the password.
- **GitHub Copilot sign-in stays available** in AIB Linking.
- **Changing the chat text size keeps the row you read** at any panel width.

### Known issues
- **Helpers are not available in WSL projects.** Subagents are.
- **Some WSL paths have not run on a real distro yet:** WSL sync and Send later in WSL. They ran against stand-ins and tests.
- **On macOS, finished-subagent clean-up cannot read the labels** on a subagent's processes, so it cannot tell which ones to shut down.
- **A chat that started before helpers became default has no helper tools** until it is restarted.
- **Sync works while both PCs are on your Tailscale and online.** Changes wait on the PC that has them.
- **Gemini and Antigravity approval shapes were recorded on Windows only,** not on Linux or in WSL.
- Carried over from 0.13.1 beta.

### Tested
Only what really ran.
- **Windows, release suites on the release commit:** the full Deno suite with all three attention modes (3,006 passed, 0 failed), the two perf tests on their own, the page tests (1,740 passed), the end-to-end worktree tests, and the update take-over test.
- **Finished-subagent clean-up on a real Ubuntu distro in WSL,** for Claude Code and Codex subagents: their processes shut down, another subagent's and the main agent's are left alone, and a stopped task ends only its own processes.
- **Finished helpers with the real keeper:** a merged helper's agent, background command and child process are gone within seconds; quitting AIB still keeps a working helper.
- **Gemini CLI 0.70.0 and Antigravity CLI 1.5.11 approvals** recorded from the real programs on Windows.
- **WSL subagent worktrees** on a real Ubuntu distro.
- **Not run on a real distro:** WSL sync and Send later in WSL. **Not run:** macOS and Linux desktops for this release.

## 0.13.1-beta

[Downloads on GitHub](https://github.com/sirkuttin/AIB/releases/tag/v0.13.1-beta)

> **Beta.** Builds are not code-signed. Expect rough edges. Install and download notes are the same as in [0.1.0 beta 1](https://github.com/sirkuttin/AIB/releases/tag/v0.1.0-beta.1).

AIB 0.13.1 beta brings Linux up to Windows: notifications you can click and answer, and a .deb install that updates itself. `aib-shared/` gets its own place and icon in Files. Everything runs on your PC.

### What's new

#### Linux notifications: click to open the chat, answer from the notification

- **Cross-agent:** the buttons work for requests from Claude Code, Codex, Gemini and every other agent.
- **Local:** AIB talks to your desktop's own notification service. Nothing leaves your PC.
- **A click opens the chat,** as on Windows.
- **The same buttons as on Windows:** **Allow** and **Deny** for an ordinary approval, **Reply** and **Open** for a question or a finished chat, **Continue** and **Open** for a stalled chat, **Retry** and **Open** for a failed turn. A risky command gets **Open** only.
- **Reply:** on KDE you type the answer in the notification. On GNOME, Reply's button opens the chat.
- **Answer anywhere and the notification closes.**
- **AIB quit?** A click still starts AIB and goes through.
- **AIB accepts clicks only from your desktop's notification service.** Another program can't press the buttons.
- **No notification service with buttons:** AIB shows plain notifications, as before.

#### .deb installs: update from the Update button

- **Install now asks for your system password** ("Authentication is required to update AIB"). AIB installs the update, restarts, and keeps your running chats, as on Windows.
- **The AIB window says when it asks for your password,** so you know the prompt is AIB's.
- **The installer checks the file itself:** it downloads the release's checksums from GitHub, checks its own copy of the file, and installs only that exact version. It never installs an older one.
- **Cancel the prompt and nothing is installed.** AIB shows why, and the `sudo apt install` line.
- **From the phone, or with Install when chats finish:** AIB marks the update ready and you click **Install now** on the PC. No password prompt pops up unasked.
- **The .deb lists the tools its installer needs,** so apt installs them with AIB.

#### Files: aib-shared/ under aib-docs, with its own icon

- **`aib-shared/` is always the second row in Files,** right under `aib-docs/`.
- **Its icon is two stacked folders in the local-only blue:** the same folder in every chat copy. The "local only" label stays.

### Fixes
- **"Started by VS Code" or "a terminal" shows on Linux and macOS** for agents running in another app.
- **A chat that lands on Linux or in WSL leaves no stray `aib-shared (from chat-…)` file** in the project.
- **Settings > AIB Linking > Codex says how to install the Codex program** when only its adapter is found.
- **Ubuntu's app menu entry has a description,** and the dock matches AIB's window to its icon.
- **Agents put each command you should run in its own code block,** so the **Run in terminal** button shows.
- **`aib-shared/` and `private/` are in AIB's own `.gitignore`.**

### Known issues
- **GNOME on Wayland may not bring AIB's window forward** when you click a notification while AIB is running. The chat still opens.
- **Some notification services (dunst, mako, swaync) have command-line tools** that can press a notification's buttons. GNOME and KDE don't.
- **A .deb updates only to versions published on GitHub.**
- **Going back to an older .deb** means installing it by hand.
- Carried over from 0.13.0 beta.

### Tested
Only what really ran.
- **Linux notifications in WSL Ubuntu** with AIB's real notification helper and a stand-in notification service: click, Allow, Deny, Reply, Continue, Retry, closing when answered elsewhere, a click after AIB quit, and a rogue program's clicks ignored, including after the service restarts.
- **.deb update in WSL Ubuntu** with real packages and a stand-in for the password prompt: two real updates that restart AIB, a cancelled prompt, a file swapped while the prompt was open, wrong checksums, an older or equal version, and a version other than the one offered, all refused with nothing installed.
- **Three independent security reviews** of the notification and .deb code; every must-fix is fixed.
- **Linux test suite on Ubuntu desktop (Deno 2.9.8):** everything passes except 8 browser-based layout and scroll tests, which are still being looked at.
- **Windows:** the release suites (Deno, Node, contract) and the update take-over test.
- **On a real Ubuntu desktop:** pending. That covers clicking notifications and the .deb password prompt.

## 0.13.0-beta

[Downloads on GitHub](https://github.com/sirkuttin/AIB/releases/tag/v0.13.0-beta)

> **Beta.** Builds are not code-signed. Expect rough edges. Install and download notes are the same as in [0.1.0 beta 1](https://github.com/sirkuttin/AIB/releases/tag/v0.1.0-beta.1).

AIB 0.13.0 beta lets you edit files in WSL projects, hands Codex chats to VS Code, Codex Desktop and the Codex CLI, and puts answer buttons on phone notifications. Google's Antigravity CLI joins the Beta agents, next to Claude Code, Codex, OMP, Gemini and Maki. One `aib-shared/` folder serves every chat, helper and subagent of a project. Everything runs on your PC. Projects that have a `private/` folder: read **Before you update** below.

### What's new

#### File editor in WSL projects: edit Linux files with the same safety as Windows files

- **Cross-agent:** a change from Claude Code, Codex or any other agent in the distro merges into your open text, as on Windows.
- **Local:** AIB reads and saves the file inside the distro through its own helper, never through `\\wsl$`.
- **WSL files open ready to edit.** Click a file in **Files** or a path in a reply, type, and save with Ctrl+S.
- **The editor keeps its guarantees:** agent edits merge, overlaps show as **Compare**, unsaved text survives a restart, and undo spans saves.
- **A save keeps the file as Linux knows it:** line endings, BOM, mode, owner and group. A symlink inside the project saves its target and stays a link.
- **A stopped distro never loses your text.** The save waits and the text stays in the tab.
- **AIB refuses edits in `.git`, in your agents' sign-in folders** (`~/.claude`, `~/.codex`, `~/.ssh` and the like) and through links that lead out of the project.
- **A paired computer with the Files switch edits and downloads WSL files** like Windows files.

#### Codex hand-off: open an AIB Codex chat in VS Code, Codex Desktop or the terminal

- **Cross-agent:** **Open elsewhere** covers Claude Code and Codex chats.
- **Local:** AIB reads only the process list on your PC to see who opens a chat.
- **`codex resume` in a terminal takes the chat within about 10 seconds.** AIB lets go at once when the chat is idle, or when its running turn ends. The Codex CLI's retry card then opens it.
- **VS Code's Codex extension and Codex Desktop get every idle Codex chat.** When either starts its Codex after AIB, AIB lets go of each idle Codex chat, once per start. A working chat, its helpers, its shells and an open question stay with AIB.
- **The Let go icon sits in a Codex chat's header** ("Let another app open this chat"). Click it to hand a chat over by hand. Once AIB has let go, the icon greys out and says "AIB already let go of this chat".
- **Send a message or click Open here to take the chat back.** AIB loads the turns written in the other app. While the other app holds the chat, AIB sends nothing: Codex lets one app write at a time.
- **WSL Codex chats work the same,** VS Code Remote-WSL included.

#### Phone notifications: answer from the notification itself

- **Cross-agent:** the buttons work for every agent's requests.
- **Local:** a tap goes from your phone to your PC over your own Tailscale network.
- **Each notification about one chat carries two buttons:** **Allow** and **Deny** for an ordinary approval, **Reply** and **Open** for a question or a finished chat, **Continue** and **Open** for a stalled chat, **Retry** and **Open** for a failed turn.
- **A risky command (push, force push, delete), AIB's merge request and a question form get Open only,** so you see the full request first.
- **Allow, Deny, Continue and Retry act without opening AIB,** under the phone's own switches: **Approve requests once** for Allow and Deny, **Send** for Continue and Retry. Each tap goes into **Phone activity**.
- **Each button works once, for that phone and that request,** for up to 12 hours. A refused tap opens the chat on the phone with a short note.
- **Reply opens the chat's message box with the keyboard up.**
- **Answer a request anywhere and its notification leaves the phone.**

#### Antigravity CLI: Google's agent for personal Google accounts, as a Beta agent

- **Cross-agent:** Antigravity chats sit next to your Claude Code, Codex, OMP, Gemini and Maki chats, with the same inbox, approvals, docs and artifacts.
- **Local:** AIB installs `agy` into its own data folder and runs it on your PC with Google's telemetry switched off.
- **Personal Google accounts (free, AI Pro and Ultra) belong here.** Since June 18, 2026, Google serves them through Antigravity CLI, and Gemini CLI takes paid API keys and Code Assist licences. The Gemini CLI card points here.
- **Install from Settings > AIB Linking > Beta agents > Antigravity CLI > Install.** AIB downloads version 1.5.11 from Google and checks its SHA-512 against the value pinned in AIB. No install script runs. An `agy` you already have is found too.
- **Sign in on the card** runs Google's paste-a-code sign-in in the card's terminal. Or paste a Gemini API key: AIB then gives `agy` a settings folder of its own, and your `~/.gemini` stays as it is.
- **In an Antigravity chat:** its model list, its modes (default, accept edits, plan) and its slash commands.

#### aib-shared/: one folder for every chat, with nothing to sync

> *"Neither a copy nor a sync be; one folder serves them all."* — AIB Linking

- **Cross-agent:** every agent of every provider reads and writes the same folder, and is told "aib-shared/ in the project folder is shared by every agent and chat, never committed."
- **Local:** the folder lives on your PC, and git never commits it.
- **One real folder in the project's main folder.** Each chat copy, helper and subagent worktree gets a link named `aib-shared` to it: a directory junction on Windows, a symlink in WSL.
- **A note a subagent writes is in the main folder at once.** Nothing is copied or moved when a worktree goes.
- **Removing a worktree takes away the link only,** never the folder it points to.

#### Linux: AIB finds npm, nvm and your agents from the app menu

- **AIB reads PATH from your interactive login shell** at start, the way VS Code does, so Node.js under nvm and adapters in `~/.local/bin` are found.
- **Agents AIB starts get the same PATH.**
- **When the shell gives nothing,** AIB adds the newest `~/.nvm/versions/node/*/bin` and `~/.local/bin`.
- macOS gets the same lookup.

#### Security: reading AIB's files gives no control over your agents

- **Cross-agent:** this guards every chat, whatever agent runs it.
- **Local:** every key stays on your PC.
- **On Windows, AIB's control keys in its data folder are encrypted to your Windows user** (DPAPI): the keeper's key, the artifact keys and each chat's tool and hook keys.
- **The AIB window keeps its session in memory only.** Each window gets a one-time start key through a private channel, and no window address carries a key. A browser tab opened from AIB's printed link connects once, and needs a new link after a reload.
- **On Linux, the keeper refuses connections from processes its agents started,** an agent's shell included.
- On macOS and Linux, the keys stay in files only your user can read.

#### Settings: your name on AIB's commits, and test builds on request

- **Name and email for AIB's commits** (Settings > AIB server) sets the author of the commits AIB makes itself: helper landings, snapshots and merges. Use the form `Name <email@example.com>`. Empty uses each repository's own git name and email. AIB never changes your repository's git settings. GitHub refuses pushes that hold a private email address, so a GitHub noreply address fits here.
- **Get test builds** (Settings > AIB server > Updates) also offers test builds from this computer's `AIB-test-feed` folder; the newer of that and GitHub wins. Off by default.

#### WSL projects: the rest of AIB works as on Windows

- **Open in new window, Ctrl+K, Ctrl+click and chat pop-out** open WSL projects and chats.
- **Open in Artifacts in Files** shows WSL files.
- **A paired computer downloads WSL project files.**

### Before you update: projects with a private/ folder

AIB 0.13 uses `aib-shared/` and leaves an existing `private/` folder as it is.

- **Your `private/` folder stays local only** in the project's main folder, and agents are told where it is. Chat copies get no link to it.
- **To move a project to aib-shared/ by hand:** quit AIB. Rename the project's `private` folder to `aib-shared`. > *"Every subagent its own ground to stand on."* — AIB Linking

- **Notifications follow you.** AIB knows which device is in use, so a question goes to the computer you are at, and to your phone when you are away. A card you answer shows which device answered it.
- **Device kinds.** Each device row has a **Phone / Computer** control, so you can change a paired device without pairing again. It only changes when you click it, and the log says who did it. A desktop browser that pairs is guessed to be a computer, whatever its width.
- **Security:** a computer's actions are classified one by one, and some never go through remotely: signing agents in, export, purge, folder delete, updates, merging worktrees and the like. The agents' credential folders (`~/.claude`, `~/.codex`, `~/.gemini`, `~/.ssh`) are blocked in remote Files, and paths are checked after they are resolved. - Agents keep running in a separate background process, so closing or updating the app doesn't cut off a turn.
- Pages and files agents make (artifacts) shown next to the chat.
- Automatic update check (once a day, can be turned off in Settings), with downloads verified against `SHA256SUMS`.
